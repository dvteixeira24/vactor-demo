# Vactor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and deploy Vactor — a voice-acting marketplace with actor profiles + audio demo clips (waveform player) and a seeded job board with offers — on Cloudflare Workers.

**Architecture:** Next.js 16 App Router served from Cloudflare Workers via the OpenNext adapter. Server Components read Cloudflare D1 through Drizzle; mutations run as Server Actions except file uploads, which stream through a route handler into R2. Auth is Better Auth (D1 + KV). Media plays via an R2-backed range-request route and a global waveform player.

**Tech Stack:** Next.js 16, React 19, TypeScript, Tailwind CSS v4, Drizzle ORM, Cloudflare D1/R2/KV, Better Auth (`better-auth-cloudflare`), Zod, Vitest, Playwright, `@opennextjs/cloudflare`, Wrangler.

**Spec:** `docs/superpowers/specs/2026-10-04-vactor-design.md`

## Global Constraints

- Runtime: Cloudflare Workers — **no Node filesystem**; use `nodejs_compat`; all bindings via `getCloudflareContext()`.
- Package manager: **pnpm** (available: 12.6.0). Node 24.
- All external input validated with **Zod** at the boundary.
- Arrays stored as JSON text columns (SQLite); dates as ISO strings / integer epochs per Drizzle defaults.
- Package manager scripts named exactly: `dev`, `build`, `preview`, `deploy`, `cf-typegen`, `db:generate`, `db:migrate`, `db:seed`, `test`, `test:e2e`.
- Upload limits: max **25 MB**; allowed MIME: `audio/mpeg`, `audio/wav`, `audio/x-wav`, `audio/mp4`, `audio/ogg`, `audio/webm`.
- Waveform: exactly **1000 peak buckets**, values 0–1, rounded to 3 decimals.
- Owned paths: `src/app/**`, `src/components/**`, `src/lib/**`, `src/db/**`, `src/auth/**`, `drizzle/**`, `scripts/**`.
- Design direction: light, editorial, casting-directory; one indigo accent; WCAG AA; honor `prefers-reduced-motion`.

## Review Focus

Inputs/conditions the spec implies but no single task's tests fully own — each has a pinned test in the task noted:

1. **Corrupt / undecodable audio file** — client decode must fail gracefully and keep the file for retry (Task 5).
2. **Range requests beyond EOF / malformed Range on `/api/audio/[id]`** — must 416 or fall back to full 200, never crash (Task 5).
3. **Duplicate offer** `(jobId, userId)` — second submit updates, never inserts a duplicate (Task 7).
4. **Clip/offer access by a non-owner** (e.g. delete someone else's clip) — rejected (Task 3/5).
5. **Empty states everywhere** (no clips, no offers, no results) — render a designed empty state, not a blank or a crash (Task 8).
